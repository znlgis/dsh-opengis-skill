## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，没有 reference 目录，正文的「环境准备」「核心 API」「典型工作流」「常见问题」按任务取用，升级旧代码前先读 v5→v6 破坏性变更表。原生端嵌入用 `skill` 加载 `maplibre-native`，动态影像瓦片后端用 `skill` 加载 `stac-cog-titiler`，大规模数据图层看 `deck-gl`；不要在技能之间 `read` 兄弟目录。
- **执行环境**：`npm install`、`npm run dev` 走 `ops_bash`，Windows 下脚本里写 `cmd /c npm run build` 比直接 `npm` 稳。dev server 与 `npx serve dist` 都是常驻进程，必须 `run_in_background` 起、`job_output` 读到 listening 行确认端口，收尾 `job_kill`，不要让 5173/3000 一直占着；换端口前先 `curl -s -o /dev/null -w '%{http_code}' http://localhost:<port>/` 看是不是已被别的服务占用。页面文件写会话工作区，不要写进只读的技能目录。
- **先探测版本**：`npm ls maplibre-gl` 看实际装的是不是 6.17.0（没装先 `npm view maplibre-gl version` 查上游最新），再 `node -e "import('maplibre-gl').then(m=>console.log(typeof m.Map))"` 确认 ESM 入口能解析、导出里有 `Map`。正文按 6.17.0 / Style Spec v25 编写；报 `Unexpected token 'export'` 是拿 UMD 思路加载了 `.mjs`，`new maplibregl.Map is not a constructor` 是 v5 的 default import 写法没改。
- **验证产物**：shell 里看不到 WebGL 画面，构建成功不代表地图出来了。至少三层：`curl -s -o /dev/null -w '%{http_code}\n'` 打 dev server 首页与 `maplibre-gl.css` 要 200；`curl -s https://demotiles.maplibre.org/style.json | head -c 80` 确认样式源可达（样式 404 会让整图空白且只在 error 事件里报）；最后要看到画面：项目里已有 Playwright/Puppeteer 时起无头浏览器截图存 PNG，再用 `read_image` 看是不是真有底图（纯色、全白、空文件都算失败），没有这套环境就用 `ask_user_question` 让用户拍板「装无头浏览器自己截/用户打开看/只交付静态构建产物」。
- **风险与权限**：`npm install` 会下载依赖并改 `package-lock.json`，装 Playwright/Chromium 是几百 MB 的环境改动，都先确认再动手；dev server 绑 `0.0.0.0` 等于把页面暴露到内网，默认只绑 `localhost`。`addProtocol` 与第三方瓦片 URL 会把请求发到外部，先核对来源与条款，别把内网地址写进样式；MapLibre 本身免 token，看到要求填 `accessToken` 的示例说明混进了 Mapbox 代码。
- **常见失败**：`WebGL2 is required` 是无头/远程桌面缺 GPU，换环境或接受无法渲染，不要为此改库；地图空白先查容器有没有显式高度、`addLayer` 是否早于 `load`；截图全黑是 `preserveDrawingBuffer` 默认 false，构造时开 `canvasContextAttributes: { preserveDrawingBuffer: true }`；`styleimagemissing` 里补图不生效是 v6 改成只通知，改用 `setMissingStyleImageResolver`。
