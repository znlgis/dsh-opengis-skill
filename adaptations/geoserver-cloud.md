## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference；正文按 GeoServer Cloud 3.0.2.1、配套 Helm chart 3.0.3 编写，部署看「环境准备与快速启动（docker-compose）」「Kubernetes（Helm）」，排障看「常见问题」，路径对照「核心 API：网关路由与端点」。数据准备与发布自动化用 `skill` 加载 `gdal`、`postgis`、`geoserver-rest-api`，不要用 `read` 去读兄弟目录的 SKILL.md。
- **执行环境**：命令走 `ops_bash`（Windows 下是 MSYS bash）。正文的 `wget` 在 Windows 不存在，改用 `curl.exe -LO`（`pwsh` 里用 `Invoke-WebRequest`）；`/tmp`、`export`、heredoc 一律换成会话工作区与单行命令。`docker compose pull/up -d` 要拉十几个镜像、启动十个服务，属长任务：用 `ops_bash` 的 `run_in_background`，再用 `job_output` 分段收日志、失败用 `job_kill` 收尾。三步以上（拉取 → 起服务 → 探活 → GetMap）先 `todo_write`。
- **先探测版本**：正文按 3.0.2.1 编写，先跑 `docker compose version`、`docker version`、`kubectl version --client`、`helm version`，再用 `curl.exe -s -u admin:geoserver http://localhost:9090/geoserver/cloud/rest/about/version.json` 确认网关后面的 GeoServer 版本。低版本差异：3.x 起不再发布 `geoservercloud/geoserver-cloud-discovery` 镜像（Docker Hub 已 404），服务发现改用 `hashicorp/consul`；旧资料的 `jdbcconfig` 后端已被 `pgconfig` 取代。同一套部署里所有 `geoserver-cloud-*` 镜像必须同标签，chart 版本（3.0.3）与镜像标签不必一致，升级前先查 chart 默认镜像标签。
- **验证产物**：分层验证——`docker compose ps` 全 Up 只是第一层，再取 `http://localhost:9090/actuator/health` 的 `{"status":"UP"}`、`http://localhost:8500/v1/catalog/services` 里 wms/wfs 已注册、网关 `.../rest/workspaces.json` 返回合法 JSON，最后发一次 WMS `GetMap` 存成 png 并用 `read_image` 真看一眼非空、坐标没错。actuator 被 profile 关掉时改用 `kubectl -n gis get pods` 判活。
- **风险与权限**：`docker compose down -v`、`helm uninstall`、删 PVC、重置 `PGCONFIG_SCHEMA` 都会连数据目录与配置一起丢；扩容到生产、`--scale wms=3` 会改资源占用。执行前用 `ask_user_question` 给「先备份快照 / 只扩容 / 重建并丢数据」三个选项。`admin:geoserver`、`PGCONFIG_PASSWORD` 与 RabbitMQ 口令写进 `.env` 且不得回显到报告或日志。
- **常见失败**：502 先查 Consul 注册与目标服务健康（`kubectl -n gis logs deploy/<wms>` 或 `docker compose logs wms > run.log 2>&1` 后 `grep -n "^ERROR" run.log`）；配置改了不同步查 RabbitMQ 可达与 `GEOSERVER_BUS_ENABLED=true`；瓦片 404 查 gwc 是否部署、`GEOSERVER_BASE_PATH` 前缀是否与请求一致（网关先 StripBasePath 再转发）。
