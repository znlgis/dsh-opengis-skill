## DeepSeek Harness 使用建议

- **加载与引用**：本技能是索引型入口：先按四个阶段定位工具，再用 `skill` 加载子技能读细节（`gdal`、`gdal-api`、`qgis-process`、`pyqgis`、`geoserver-rest-api`、`openlayers`、`cesiumjs`、`stac-cog-titiler`），别指望本文给全参数；影像云原生链路（COG 出图、STAC 编目、TiTiler 动态切片）从 `stac-cog-titiler` 进。两份参考要分段取：`reference/data-stages.md` 先看开头 `## Contents` 定位阶段一至阶段四的小节，再按 `offset`/`limit` 读；`reference/workflow-cheatsheets.md` 只取端到端示例、内置算法速查、GDAL 命令速查几节，用 `grep` 定位比整读快。
- **执行环境**：四个阶段的命令都在 `ops_bash` 里跑。Windows 没有 `apt-get`/`sudo`：GDAL 走 OSGeo4W 绝对路径或 conda-forge，QGIS 用官方安装包（`qgis_process` 随安装自带），GeoServer 用 Docker。`QT_QPA_PLATFORM=offscreen` 在 bash 写成单条命令前缀，在 `pwsh` 写 `$env:QT_QPA_PLATFORM = "offscreen"`。起服务用后台作业：`docker run -d -p 8080:8080 docker.osgeo.org/geoserver:3.0.2` 以 `run_in_background` 启动，再用 `job_output` 轮询就绪，别让一次调用阻塞；收尾 `job_kill`。`qgis_process` 参数多，先 `qgis_process help <id> --json`。
- **先探测版本**：`gdalinfo --version` / `ogrinfo --version`（正文基准 GDAL 3.13.3）、`qgis_process --version`（基准 QGIS 4.2.3，LTR 3.44.15；4.x 与 3.44 的 Processing 算法 ID 和 Qt 版本不同，混用会报未知算法）、`curl -u admin:geoserver "http://localhost:8080/geoserver/rest/about/version.json"`（GeoServer 3.0.2）、`python3 -c "from osgeo import gdal; print(gdal.VersionInfo())"`。缺哪个阶段的工具就加载相邻子技能，不要硬拼整条链路。
- **验证产物**：每阶段产物落工作区（GeoPackage/COG/GeoJSON），下一阶段只读产物。转换后 `ogrinfo -so -al`、`gdalinfo -json` 核对 CRS、范围与要素数；发布后 `curl` 回读 `layers/demo:roads_buffer.json`，要求 HTTP 200 且含 `"enabled": true`，或查 `GetCapabilities`；WMS 出图后用 `read_image` 看一眼贴图是否真有内容。要交付的 GeoJSON、地图包用 `present` 列出。任一步失败先修本阶段产物，别带坏数据往下走。
- **风险与权限**：`gdal_edit.py` 就地改元数据、`ogr2ogr` 同名输出、GeoServer `?recurse=true` 删除都不可逆，先备份并确认路径；GeoServer 默认 `admin:geoserver` 只用于本地演示，真实凭据不进命令行与回复。装 GDAL/QGIS、拉镜像、监听端口、连生产库前用 `ask_user_question` 让用户选方案；对外暴露 8080 端口要单独确认。
- **常见失败**：`qgis_process` 在无显示器环境崩溃先设 `QT_QPA_PLATFORM=offscreen`；上传 Shapefile 失败先打成 ZIP 且根目录含 `.shp/.shx/.dbf/.prj`；报找不到 `gdal_calc.py` 是缺 Python 绑定，改用 `qgis_process run gdal:rastercalculator`；REST 401/403 查 Basic Auth 与用户权限；大栅格内存不足先 `gdal_translate -srcwin` 分块并调 `GDAL_CACHEMAX`、`GDAL_NUM_THREADS`。
- **工作流**：端到端链路先 `todo_write` 拆成「取数→转换→分析→发布→回读」，阶段间以文件为契约；多数据源核对这类互不依赖的活可以 `subagent` 并行，但发布步骤必须串行等验证通过。
