## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，没有 reference 目录，正文的「环境准备」「C API 基础骨架」「核心 API」「典型工作流」「常见问题」按需跳读即可。要对照 Java 上游实现用 `skill` 加载 `jts`，要在 Python 侧复现同一套几何运算用 `skill` 加载 `shapely`（它内嵌的 GEOS 版本可能与本机不同，跨语言比对前先核对），入库与发布用 `skill` 加载 `postgis`、`gdal`；不要用 `read` 翻兄弟目录的 SKILL.md。
- **执行环境**：编译与运行走 `ops_bash`（Windows 下是 MSYS bash，工程建在 `/d/work` 这类路径）。正文的 `apt-get`/`sudo` 在 Windows 不成立：装库走 vcpkg（`vcpkg install geos:x64-windows`）或 conda-forge（`conda install -c conda-forge geos`），装好后确认 `geos_c.dll` 与 exe 同目录或在 `PATH` 里；MSVC 工程用 `pwsh` 调 `cl /I <include> demo.c <lib>\geos_c.lib`，不要拿 bash 的 `-lgeos_c` 硬套。源码构建 `cmake -DCMAKE_BUILD_TYPE=Release -DCMAKE_INSTALL_PREFIX="$PWD/install" ..` 后 `cmake --build . --parallel`，整套几分钟起，用 `run_in_background` 起作业再 `job_output` 收尾，不要在前台干等；安装前缀先指到会话工作区，别急着写系统目录。
- **先探测版本**：`geos-config --version` 与 `pkg-config --modversion geos` 两个都跑：前者查二进制、后者查 `.pc` 登记值，两者不一致说明 PATH 里混了多套安装。再确认编译期头文件版本 `grep -h "GEOS_VERSION " "$(geos-config --prefix)/include/geos/version.h"`，与 `geos-config --version` 对不上就是 include 与 lib 不同源，链接阶段会报符号找不到。正文按 3.15.0 编写；3.12 起 WKTWriter 默认 trim、3.9 起默认 OverlayNG，按探测到的实际版本决定是否还要显式设置。
- **验证产物**：别只看程序退出码。用 `write` 落一个最小 C 程序：两块 10x10 面错位 5 相交，`GEOSArea` 应恰为 25 而不是 0；再 `GEOSBuffer` 半径 0.5，面积应略大于 25。`GEOSisValid` 必须为 1，把输出 WKT 重新读回再比一次面积与顶点数；Windows 上再 `dumpbin /dependents demo.exe` 确认真的链到 `geos_c.dll`，否则运行期才报找不到模块。要看几何形状就写 WKT 转 PNG 的旁路，用 `read_image` 看一眼，纯白图与空结果等价。
- **风险与权限**：`make install` 默认写 `/usr/local`、conda/vcpkg 安装会改环境变量与 PATH，执行前用 `ask_user_question` 给出「装到工作区前缀/替换系统库/取消」三个选项。本机若已有 QGIS、PostGIS、GDAL 自带的 `geos_c.dll`，覆盖它会让这些程序一起坏掉，先备份或改用独立前缀；升级 GEOS 后 C++ 侧必须重编（无 ABI 承诺），生产几何回归先在只读副本上跑。
- **常见失败**：`TopologyException: side location conflict` 先 `GEOSisValid`+`GEOSMakeValid`，别急着加重试；`undefined reference to GEOSIntersection` 是 C API 却只链了 `-lgeos`；谓词结果反了是把 char 当布尔（1 真/2 假/0 异常）；`free()` 释放 `GEOSWKTWriter_write` 返回的字符串在 Windows 上必崩，改用 `GEOSFree`。
