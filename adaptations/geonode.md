## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference；正文按 GeoNode 5.1.1 编写，部署读「环境准备 → Docker Compose」，接口读「核心 API」的认证、检索、上传三张表，「典型工作流」给的是上传到取 OGC 地址的完整序列。GeoServer 侧细节用 `skill` 加载 `geoserver`，元数据库用 `skill` 加载 `postgis`，不要在技能之间 `read` 兄弟目录。
- **执行环境**：`docker compose`、`python create-envfile.py`、`curl` 走 `ops_bash`；Windows 下 Docker Desktop 的路径改写会弄坏 `-v "$PWD/x:/x"`，改用 `-v "$(pwd -W)/x:/x"` 或加 `MSYS_NO_PATHCONV=1`。`docker compose up -d` 与 `logs -f django` 是长任务：启动放后台作业，`job_output` 读到 `Executing UWSGI server uwsgi --ini /usr/src/app/uwsgi.ini` 这一行再往下走，不要用固定 sleep 猜就绪。
- **先探测版本**：`curl -s http://localhost/version.txt` 确认 5.1.1，`docker compose ps` 看 django、celery、redis、postgis 是否都在跑；正文按 5.1.1 编写，基于 Django 5.2.18、Celery 5.6.3，源码分支要对应 `5.1.x`。GeoNode 版本与数据库迁移绑定，升级后报 `AttributeError` 或表不存在，先 `docker compose exec django python manage.py migrate`，不要回退代码。
- **验证产物**：上传返回 201 不构成发布成功。依次核对：`logs -f django` 无 Traceback；`GET /api/v2/resources?search=...` 能查到资源且 `subtype` 正确；`resource.alternate` 与 `links[]` 里的 `OGC:WMS` 地址齐全；最后对该 WMS 发一次 `GetMap`，要 200 且 `size_download` 大于 0，`GetCapabilities` 里能找到同一 `alternate`。响应与日志先重定向到文件，再用 `grep` 取关键行，别把整个 JSON 打进上下文。
- **风险与权限**：`action=replace` 整体替换数据、删除资源、`manage.py migrate`、恢复 `pg_dump` 都不可逆，执行前用 `ask_user_question` 让用户确认 `resource_pk` 与备份；两个库 `geonode` 与 `geonode_data` 必须同时备份。`create-envfile.py --env_type prod` 会尝试申请 Let's Encrypt 证书，域名不可达会卡住，试跑先用 `dev`。`ADMIN_PASSWORD`、`clientid/clientsecret` 与 Basic 串从 `.env` 读，不要回显到命令输出或报告。
- **常见失败**：`docker compose up` 后 502 是 django 还在迁移或 collectstatic，或启动失败，用 `job_output` 看首个 Traceback；上传 401 是 `Authorization` 头缺失或 base64 拼错（Windows 下用 `pwsh` 的 `[Convert]::ToBase64String` 生成，别拿 MSYS 的 `base64` 猜编码）；403 是用户缺 `base.add_resourcebase` 权限；GetMap 空白图先查图层 bbox 与 CRS 是否匹配。
