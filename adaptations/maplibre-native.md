## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，没有 reference 目录；正文「环境准备」按 Android/iOS/Node/C++ 分块，「典型工作流」三条链路与「常见问题」表先对症状再深挖。样式 JSON 与前端共用，浏览器侧问题用 `skill` 加载 `maplibre-gl-js`，瓦片与影像后端用 `skill` 加载 `stac-cog-titiler`；不要 `read` 兄弟目录。
- **执行环境**：本队列是 Windows + MSYS bash，四个平台分支里只有 Node 能完整跑通。Node 端 `npm install @maplibre/maplibre-gl-native` 走 `ops_bash`，预编译二进制只覆盖 Node 22/24/26，`node -v` 不在其中就别试；Android 需要 JDK 与 Android SDK（`./gradlew` 构建动辄十几分钟），iOS 的 Bazel/Xcode 只能在 macOS 上跑，本机没有就明说做不了，不要编造构建结果。真跑构建与模拟器时用 `run_in_background` 起作业、`job_output` 跟日志（首次会下载 Gradle 依赖与 SDK），失败再 `job_kill` 收尾。
- **先探测版本**：Node 端 `npm ls @maplibre/maplibre-gl-native` 应为 6.4.1，再 `node -e "const m=require('@maplibre/maplibre-gl-native'); console.log(typeof m.Map)"` 必须打印 `function`，打印 `undefined` 多半是平台或 Node 大版本不在预编译列表内；Android 用 `./gradlew :app:dependencies --configuration debugRuntimeClasspath | grep maplibre` 核对 13.x，iOS 查 `Podfile.lock` 里的 `MapLibre (7.0.0)`，`xcodebuild -version` 在本机大概率直接报「不是内部或外部命令」，那就是没有 iOS 分支。正文按 Android 13.5.4/13.7.1、iOS 7.0.0、Node 6.4.1 编写。
- **验证产物**：Node 分支是唯一能端到端验证的：写一个渲染脚本（`map.render({width:512,height:512,zoom:2,center:[0,0]}, cb)` 拿 RGBA 缓冲写 `tile.png`），再用 `read_image` 看是不是真出一张世界地图——全透明、纯色块、0 字节都算失败，最常见根因是 `request` 回调对某些 `kind` 没 `callback`；同时断言输出 512x512 且 `map.release()` 已调用。Android 有模拟器时 `adb exec-out screencap -p > shot.png` 再用 `read_image` 复核，没有设备就只报告「编译通过」，不能写「地图已显示」。
- **风险与权限**：`npm install` 会下载原生二进制、`git clone --recurse-submodules` 拉整个仓库（数 GB）、装 Android SDK/NDK 与启动模拟器都改环境，动手前用 `ask_user_question` 确认磁盘与时间成本；Android `MapView` 生命周期漏转发会泄漏渲染线程，改这类代码按「编译 → 装机 → 看画面 → `adb logcat` 无崩溃」四步走。离线区域下载受瓦片服务 `Cache-Control` 与服务条款约束，批量抓取前确认授权；样式里不要写内网瓦片地址。
- **常见失败**：Android 绿屏或纯色块是 `MapLibre.getInstance()` 没在 `MapView` 之前调用；跑起来却报找不到 `org.maplibre.android.*` 是依赖坐标写成了旧 Mapbox 的；clone 后缺头文件是没拉 submodule，补 `git submodule update --init --recursive`；iOS 7.0.0 起伞头文件改名 `MapLibre.h`，`#import <Mapbox/Mapbox.h>` 要同步改。
