## DeepSeek Harness 使用建议

- **加载与引用**：正文按 GeoPandas 1.2.0 编写，主文件覆盖 IO、`sjoin`/`overlay`/`clip`、绘图与常见问题；`GeoSeries`/`GeoDataFrame` 的完整签名在 `reference/core-api.md`——先 `read` 开头的 `## Contents` 定位小节，再按 `offset`/`limit` 分段，或用 `grep` 搜 `to_file(`、`buffer(` 之类签名，不要整文件硬读。底层几何用 `skill` 加载 `shapely`，命令行转换用 `skill` 加载 `gdal`。
- **执行环境**：`python`/`pip` 命令走 `ops_bash`，Windows 上用 `pwsh` 设 `$env:` 更稳；先 `python -c "import sys; print(sys.executable, sys.version)"` 确认解释器不是 QGIS/GDAL 自带的那个。装 `geopandas[all]` 属环境改动，先 `ask_user_question` 征得同意；批量读几百个文件或跑大面 `overlay` 时用后台作业，`job_output` 看进度，不要再串行空等。
- **先探测版本**：`python -c "import geopandas as gpd; print(gpd.__version__, gpd.options.io_engine)"`；正文按 1.2.0 / Python >= 3.11 编写，低版本缺 `make_grid`、`read_file_info`（均为 1.2 新增）与 `to_parquet(write_covering_bbox=...)`；1.2 里 `buffer(resolution=...)` 已弃用改 `quad_segs`。再查 pyogrio 后端：`python -c "import pyogrio, pyproj; print(pyogrio.__version__, pyproj.__version__, pyproj.datadir.get_data_dir())"`，`fid_as_index`、`use_arrow`、`bbox` 参数都由 pyogrio 提供，pyogrio 低于 0.8 或 PROJ 目录为空正是 `CRSError` 与 `read_file_info` 不可用的根因。
- **验证产物**：写完立刻重开核对：`gdf = gpd.read_file("out.gpkg", layer="result"); print(gdf.crs, len(gdf), gdf.is_valid.all(), gdf.total_bounds)`，并确认面积与长度是在投影坐标系下算的（经纬度下 `.area` 的单位是平方度）。只想按矩形范围裁剪时给 `gpd.clip()` 传四元素范围（如 `(minx, miny, maxx, maxy)`）会走更快的 `clip_by_rect()`，比多边形裁剪快但结果不保证拓扑有效，边角情形可能与多边形裁剪略异，交付前用 `is_valid` 复核。`to_parquet` 回读要核对列名、CRS 与 `schema_version`：不传时默认写 1.1.0，显式写 `"2.0.0"` 下游可能读不了；`write_covering_bbox=True` 才让后续 `read_parquet(bbox=...)` 真正生效。制图产物落成 PNG 后必须用 `read_image` 看一眼范围、图例与空几何，成品用 `present` 交付。
- **风险与权限**：`to_file()` 默认整表覆盖、`to_postgis(if_exists="replace")` 会删表重建，执行前用 `ask_user_question` 确认路径与表名；连接串里的密码不要出现在命令、日志或回答里。Shapefile 字段名超 10 字符会被截断且不支持空值与日期时间，要保真就换 `.gpkg` 或 GeoParquet。
- **常见失败**：`AttributeError: module 'geopandas' has no attribute 'make_grid'` / `read_file_info` 是装到了 1.2 之前的版本，先确认版本再改代码；`ValueError: GeoDataFrame does not support multiple columns using the geometry column name` 是存在重名列，用 `set_geometry()` 或先改名；`sjoin` 无结果先比两个 GDF 的 `.crs`；`to_crs("EPSG:3857")` 抛 `CRSError` 是 PROJ 数据目录缺失，不是坐标写错；`DriverError` 写入失败先查驱动名与文件是否被占用。
