## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference；正文按 DuckDB 2.0.0 编写，函数签名查「核心 API」，报错对照查「常见问题」，端到端流程看「典型工作流」。与 GeoPandas 互转用 `skill` 加载 `geopandas`，落盘格式与投影用 `skill` 加载 `gdal`、`proj`；不要在技能之间 `read` 兄弟目录，正文里的相对链接只作目录提示。
- **执行环境**：`pip install duckdb==2.0.0` 或官方 CLI 走 `ops_bash`；扩展装在 `~/.duckdb/extensions/<version>/<platform>/`（Windows 是 `%USERPROFILE%` 下的同名目录），离线环境整目录拷入即可。正文的 `INSTALL AND LOAD spatial;` 是 2.0 起的一条语句，旧版拆两步。大批量 `ST_Read` 与空间 join（GDAL 单线程、索引未必被选中）用后台作业，`job_output` 看进度、`job_kill` 收尾；动手前 `todo_write` 列出「验扩展 → 落表 → 投影 → 叠加 → 回读」。
- **先探测版本**：`SELECT duckdb_version(), duckdb_proj_version();` 拿库与 PROJ 版本；正文按 2.0.0 编写，`ST_Area_Spheroid`、`ST_CoverageUnion_Agg` 属较新函数。再跑 `SELECT extension_name, loaded FROM duckdb_extensions() WHERE extension_name='spatial';`，loaded 为 true 才算就绪；扩展没有独立版本号，随 DuckDB 版本匹配，报不匹配时先核对 DuckDB 本身。CRS 相关报错另查 `SELECT * FROM duckdb_coordinate_systems();`。
- **验证产物**：先分清新连接有没有 LOAD：内置的只有 `ST_GeomFromWKB`、`ST_AsWKB`、`ST_AsWKT`/`ST_AsText`、`ST_Intersects_Extent`（`&&`）、`ST_CRS`、`ST_SetCRS`，其余 `ST_*` 报 "does not exist" 是扩展没加载而不是 SQL 语法错。写完 Parquet 立刻回读 `SELECT count(*), ST_GeometryType(geometry), ST_IsValid(geometry) ...` 看类型与无效几何分布，再用 `ST_Extent_Agg(geom)` 或 `ST_Transform` 后的包围盒核对坐标范围是否落在预期 CRS 内；MVT 检查 `ST_AsMVTGeom` 裁剪后的空几何比例，别把全空瓦片当成功。
- **风险与权限**：`COPY ... TO`、`CREATE OR REPLACE TABLE`、`DROP TABLE` 会覆盖文件或表，`INSTALL spatial` 会联网下载；执行前用 `ask_user_question` 确认目标路径与是否允许覆盖，优先写新文件名。CRS 是类型的一部分（`GEOMETRY('EPSG:4326')` 与无 CRS 的 GEOMETRY 是不同类型），跨 CRS 二元运算先 `ST_Transform`，没有 PostGIS 的 `ST_SRID` 可依赖，别按 PostGIS 习惯写。连生产库时不要回显连接串与凭据。
- **常见失败**：`Extension spatial is not installed` 是只 LOAD 没 INSTALL 或离线拉不到扩展；`Unknown coordinate system` 是 CRS 标识未注册（EPSG 全集要 LOAD spatial 后才注册），必要时 `SET ignore_unknown_crs = true`；带 CRS 的列在旧库文件上报 `storage versions prior v1.5.0`，用 `ATTACH ... (STORAGE_VERSION 'v1.5.0')` 重建或 EXPORT/IMPORT 迁移；`ST_Area` 返回极小值是经纬度下按平方度算，改 `ST_Area_Spheroid` 或先投影。
