## DeepSeek Harness 使用建议

- **加载与引用**：正文给命令行语法、`help --json` 的结构、`run` 的 JSON 结果与常见报错；内置算法 ID、参数类型与枚举索引查 `reference/algorithm-cheatsheet.md`。先 `read` 文件开头的目录定位到目标算法小节，再用 `grep` 搜算法 ID（如 `native:buffer`），不要整份读。需要 Python 里循环调用时用 `skill` 加载 `pyqgis`，栅格导出后的检查加载 `gdal`。
- **执行环境**：命令走 `ops_bash`（Windows 是 MSYS bash，可执行文件写 `/c/Program\ Files/QGIS\ 4.2/bin/qgis_process.exe`，路径含空格必须整体加引号）；`$env:QT_QPA_PLATFORM = "offscreen"` 这类环境变量赋值走 `pwsh`，正文的 `export QT_QPA_PLATFORM=offscreen` 在 bash 里只能写成单条命令前缀 `QT_QPA_PLATFORM=offscreen qgis_process ...`。Linux 的 `sudo apt install qgis` 不可用，Windows 上装 OSGeo4W 组件或直接跑容器 `docker run --rm -v "$PWD:/data" qgis/qgis:ltr qgis_process --version`（容器内写 `/data/...`，别把宿主 `D:\...` 路径传进去）。批量循环与全量处理用后台作业起，`job_output` 看进度，`job_kill` 停掉跑偏的任务；三次以上步骤先 `todo_write` 列「探测 → help 取参 → 跑单个 → 批量 → 校验」。
- **先探测版本**：正文按 QGIS 4.2.3（stable）与 LTR 3.44.15 编写，`qgis_process` 自 3.16 起才有。先跑 `qgis_process --version`，低于 3.16 只能退回 `pyqgis` 的 `processing.run()`；用容器时用镜像 tag（`stable` / `ltr`）确认，不要假设本机 PATH 里的就是 4.2。启动慢时加 `--no-python`、`--skip-loading-plugins`，但依赖 Python 插件 provider（`saga` 等）的算法就别加。
- **验证产物**：`run ... --json` 的 `results.OUTPUT` 是实际写出的绝对路径，用它的值去校验，不要自己拼路径。矢量跑 `ogrinfo -so out.gpkg 图层名` 核对要素数、CRS、几何类型；栅格跑 `gdalinfo -json out.tif` 核对尺寸、CRS、NoData；切片或渲染出图用 `read_image` 真看一眼。正文明确：日志里出现 `returned non-zero` 时即使进程退出码为 0 也算失败，所以要 `grep -n "returned non-zero" run.log` 再下结论，别只看 `$?`。
- **风险与权限**：`OUTPUT=` 指向已有文件会被直接覆盖，`--project_path=` 会加载项目里的数据源与数据库凭证；覆盖已有图层、启动 Docker、安装 QGIS、把含密码的工程传给外部环境前用 `ask_user_question` 让用户在「换名输出 / 覆盖 / 先备份」之间选。`qgis_process run` 每次新起一个 QGIS 进程（数秒开销），千级文件别用 shell 循环硬扛，改单进程 PyQGIS。日志先重定向到 `run.log` 再 `grep`，不要把整段 JSON 日志刷进上下文。
- **常见失败**：`Algorithm <id> not found!` 先用 `qgis_process list` 核对 provider 前缀（`native:`/`gdal:`/`grass:`），插件 provider 还要求 `metadata.txt` 里 `hasProcessingProvider=yes`；`The following mandatory parameters were not specified` 回看 `help --json`；枚举参数传数字索引而不是文本；多值参数在 `--` 之后重复同一键（`LAYERS=a.shp LAYERS=b.shp`）；路径含空格或中文加引号并用绝对路径。
