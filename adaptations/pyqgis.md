## DeepSeek Harness 使用建议

- **加载与引用**：正文主文件给高频类与方法表，完整参数与示例在 `reference/vector-raster-layers.md`（矢量/栅格图层、要素读写、数据提供者 URI）和 `reference/processing-rendering.md`（`processing.run` 参数、地图渲染、`QgsLayoutExporter` 导出、典型工作流）。先用 `read` 读文件开头的目录定位小节，再按 `offset`/`limit` 跳读，或用 `grep` 搜类名，不要把两份参考整份读进上下文。要命令行跑算法时用 `skill` 加载 `qgis-process`，纯几何计算加载 `shapely`。
- **执行环境**：必须用 QGIS 发行包自带的解释器（4.2 在 `C:/Program Files/QGIS 4.2/apps/Python312/python.exe`，LTR 在 `QGIS 3.44` 下同构），系统 Python `pip install qgis` 装不上绑定。命令走 `ops_bash`（Windows 是 MSYS bash，解释器路径写成带引号的 `/c/Program\ Files/...` 形式）；只在 PowerShell 能表达的写法（`$env:QT_QPA_PLATFORM = "offscreen"`）走 `pwsh`，正文的 `export QT_QPA_PLATFORM=offscreen` 在 bash 里只能作单条命令前缀。批量渲染与长脚本用后台作业起，再 `job_output` 收进度、`job_kill` 收尾。
- **先探测版本**：正文按 QGIS 4.2.3（最新）与 LTR 3.44.15 双版本编写。先跑 `python -c "from qgis.core import Qgis; print(Qgis.QGIS_VERSION)"` 确认版本，再确认 prefix 指向哪套安装；4.x 与 3.x 的类与方法有出入，低版本没有的 API 不要照抄，拿不准先查 `qgis.org/pyqgis/4.2/` 的签名。3D 模块是 `qgis._3d`（下划线），写成 `qgis.3d` 会 ImportError。
- **验证产物**：独立脚本按 `QgsApplication` → `initQgis()` → 处理 → `exitQgis()` 收尾，中途抛异常也要保证退出，否则残留进程占着文件锁。写出后重新 `QgsVectorLayer(path, name, "ogr")` 打开，核对 `isValid()`、`featureCount()`、`crs().authid()` 三项；`processing.run()` 只返回路径，不等于算法成功，必须二次打开。渲染或布局导出的 PNG/PDF 用 `read_image` 真看一眼是否空白、范围对不对，成品用 `present` 交付。建议先跑正文的最小闭环（`native:buffer` + `assert layer.isValid()`）再往上叠逻辑。
- **风险与权限**：`startEditing()`/`commitChanges()`、`QgsVectorFileWriter` 覆盖已有路径、`QgsProject.write()` 都会就地改写源数据或工程文件，动手前先备份或把中间结果写 `memory:`；覆盖已有输出、安装 QGIS、连 PostGIS 生产库之前用 `ask_user_question` 给「换名输出 / 覆盖 / 先备份」三个选项。`postgres` provider 的 URI 可能带明文口令，命令、日志与回复里都不要回显；`QgsApplication.messageLog()` 与 stderr 重定向到 `run.log` 后再分段看。
- **常见失败**：`import qgis.core` 失败先查解释器与 `PYTHONPATH`（Windows 指向 `apps/qgis` 下的 `python` 目录）；图层 `isValid()` 为 false 时打印 `layer.error().message()` 并核对 provider 拼写（`ogr`/`gdal`/`postgres`）；`processing.run()` 报算法不存在是漏了 `Processing.initialize()` 或插件未启用；无显示环境崩溃设 offscreen 平台；渲染空白先查 `QgsMapSettings` 的 extent、CRS 与输出尺寸。
