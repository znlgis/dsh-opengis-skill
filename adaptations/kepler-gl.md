## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference。正文按 Kepler.gl **3.3.0-alpha.20**（npm `latest` 与 GitHub Release 一致，仍是 3.3 预发布线、4.0 无稳定版）与 Python 侧 `keplergl` **0.4.0** 编写。按任务读：「环境准备」区分 npm 整包/子包、UMD、Jupyter 三条路；「核心 API」四节讲 dataset 结构、Redux 接入、`addDataToMap`、配置导出；「常见问题」表的报错原文可直接对照。定位性细节（Redux 接线、config 还原）要先读完全节再写代码，组件 prop 表在「KeplerGl 组件」。自定义图层底座用 `skill` 加载 `deck-gl`，数据预处理用 `skill` 加载 `geopandas`。
- **执行环境**：npm/pip 命令走 `ops_bash`（Windows 下是 MSYS bash），`chrome`、`Get-Command` 这类走 `pwsh`。安装依赖（`npm install kepler.gl` 会拉 deck.gl、maplibre 等上百个包）和 `npm run build` 都是长任务：用 `ops_bash` 的 `run_in_background` 跑，`job_output` 分段收日志，失败用 `job_kill` 收尾；输出重定向到 `build.log` 再 `grep -n "ERR\|error" build.log`，别把整段 webpack 输出打进上下文。没有浏览器可用的环境无法验证 WebGL 渲染，不要假装渲染成功。三步以上（装包 → 建工程 → build → 起静态服务）先 `todo_write`。
- **先探测版本**：`npm ls kepler.gl @kepler.gl/components @kepler.gl/actions` 一次确认主包与子包版本是否一致（正文明确要求子包与主包同为 3.3.0-alpha.20，混版会出现难定位的运行时错误）；Python 侧 `python -c "import keplergl; print(keplergl.__version__)"` 应为 0.4.0。差异点：3.3 线是预发布，写 `^3.3.0` 可能解析不到 alpha 版本，要精确锁定；`keplergl` 0.4.0 依赖 Python >= 3.9、JupyterLab >= 4 或 Notebook >= 7，conda-forge 尚停在 0.3.2，要 0.4.0 只能用 pip。不看版本直接抄正文示例是这类项目最常见的返工来源。
- **验证产物**：`npm run build` 通过只说明 TypeScript/打包没问题。再 `npx serve dist` 起静态服务（后台作业），用浏览器或无头浏览器打开页面截图，再用 `read_image` 真看一眼：底图有没有出来、有没有图层、侧栏数据条数对不对；同时看控制台第一条报错。Python 侧验证 `save_to_html` 的输出时，检查 HTML 文件确实含内嵌数据、浏览器打开后图层可见，成品用 `present` 交给用户。判据是「图上看得见正确图层」，不是「build 退出码 0」。
- **风险与权限**：装 npm/pip 包、把用户数据写进可分享的 HTML、把含 token 的工程提交进仓库都要先确认——用 `ask_user_question` 给「只装本地 / 用 Docker node 镜像跑 / 先不装」这类选项。Mapbox token 有计费与泄露风险：只用 CARTO/MapLibre 样式时 `mapboxApiAccessToken` 传空串，绝不硬编码进配置或 HTML。
- **常见失败**：组件空白且控制台报 `Could not find ... in the context of Connect(...)`，是 reducer 没挂 `keplerGl` 键或 `getState` 指错；有数据没图层查 `datasets.info.id` 与 `config` 的 `dataId` 是否一致、字段类型是否为数值；时间轴不生效是缺少 `{type: 'timestamp', format: ...}`；点位全堆 (0,0) 是坐标系没转 EPSG:4326；`Cannot find module '@kepler.gl/components'` 是装了整包却按子包路径 import。一次 `addDataToMap` 塞几十万行会卡死主线程，先聚合或用 Arrow。
