## DeepSeek Harness 使用建议

- **加载与引用**：正文按 GeoTools 35.2（JDK 17）编写。读文件顺序：先看「环境准备与快速集成」的仓库配置与模块表，再按任务跳「CRS 与坐标转换」「CQL / ECQL」「几何操作」。矢量读写完整示例在 `reference/vector-io.md`、栅格与 StreamingRenderer 出图在 `reference/raster-rendering.md`：先用 `read` 读文件开头的小节清单，再按 `offset`/`limit` 取用，或 `grep` 搜 `FileDataStore`、`StreamingRenderer` 定位，不要整篇读。几何算法细节用 `skill` 加载 `jts`，发布链路用 `skill` 加载 `geoserver`。
- **执行环境**：命令走 `ops_bash`（Windows 下是 MSYS bash）。正文的 `mvn`/`java` 要先探测：`java -version` 必须是 17（35.x 用 JDK 8/11 编译直接失败），`mvn -v` 不存在时用 Maven wrapper 或官方 zip 解压后把 `bin` 加进 PATH；正文里的 `sudo apt-get install openjdk-17-jdk` 在 Windows 改用 Temurin 官方安装包或 `conda install -c conda-forge openjdk=17`，装不了本机 JDK 就退回 Docker（`docker run --rm -v "$PWD:/w" -w /w maven:3.9-eclipse-temurin-17 mvn ...`）。首次 `mvn` 要下载 OSGeo 仓库里几百 MB 依赖：用 `ops_bash` 的 `run_in_background` 跑，`job_output` 收日志，卡住用 `job_kill` 收尾。
- **先探测版本**：`mvn dependency:tree -Dincludes=org.geotools` 确认真的解析到 35.2 且没被别的依赖压回旧版（GeoTools 不在 Maven Central，仓库里没 `repo.osgeo.org` 就直接失败）。正文按 35.2 编写，对应 JDK 17、JTS 包名 `org.locationtech.jts`；低版本差异：≤33 分支是 JDK 11、34 起才要 17，老教程里的 `com.vividsolutions.jts` 在 20+ 已废弃。JDK 21 是 35.x 的可选支持，别用 8/11 硬跑。`pom.xml` 里 `<geotools.version>` 统一成一个属性，别混版本。
- **验证产物**：`mvn -q -DskipTests package` 只说明编译过，必须再跑一个最小 main：`FileDataStoreFinder` 打开 shapefile → `getFeatures()` 打印 count、schema 与 CRS → `JTS.transform` 重投影后打印首点坐标。写出的 GeoPackage/PNG 用独立命令回读，渲染图用 `read_image` 真看一眼不是空白、图例与范围对。`CRS.decode("EPSG:4326")` 抛异常说明缺 `gt-epsg-hsql`；`getDataStore()` 返回 null 说明对应 SPI 模块没进 classpath。`DataStore`/`SimpleFeatureIterator`/`MapContent` 没 dispose 会导致文件锁与不写盘，验证前先确认进程已退出。
- **风险与权限**：写 PostGIS/Oracle 生产库、`SimpleFeatureStore` 批量覆盖、跳过测试打包上线都不可逆，动手前用 `ask_user_question` 给「只读实例 / 写到新表 / 直接写正式库」三选项；连接串、用户名、密码只放环境变量且不得回显到报告。`mvn clean` 会删本地产物，确认目录再跑。
- **常见失败**：出现 `com.vividsolutions.jts` 是包名没升级；`CRS.decode` 报 `No such authority code` 多半缺 EPSG 模块；文件句柄泄漏或数据未写盘是漏了 `dispose()`/`try-with-resources`；多线程共享 `SimpleFeatureIterator` 会抛异常，每线程各开一个。把 `mvn -X` 日志重定向到 `run.log` 再 `grep -n "BUILD FAILURE" run.log`，不要全文读。
