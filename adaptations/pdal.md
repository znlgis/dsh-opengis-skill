## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference 目录；参数不确定时先跑 `pdal --options filters.smrf` 或 `pdal --drivers` 取运行时定义，别凭记忆写 stage 参数——正文的算子参数表与这些命令输出以实际版本为准。管线较长时用 `write` 把 JSON 存成工作区里的 `pipeline.json`，复用和逐条改动都比命令行内联可靠；复杂管线按「读取→裁剪/重投影→过滤→写出」分段拼，出错好定位。需要 DEM 后处理时用 `skill` 加载 `gdal`。
- **执行环境**：`pdal info/translate/pipeline/--drivers` 走 `ops_bash`；`Get-Command pdal` 或带反斜杠的 Windows 路径参数走 `pwsh`。本机 Windows 无 `sudo`/`apt`：PDAL 来自 conda-forge（`conda install -c conda-forge pdal python-pdal`）、OSGeo4W，或容器 `docker run --rm -v "$PWD":/data -w /data pdal/pdal pdal pipeline pipeline.json`（容器内路径写 `/data/...`，不要传宿主 `D:\...`）。整片点云处理、DEM 全量栅格化放后台作业，用 `job_output` 收日志、`job_kill` 收尾。
- **先探测版本**：`pdal --version` 与 `pdal --drivers`；正文按 2.10.2 编写，`pdal ground` 自 2.6 弃用、2.7 移出默认安装、2.8 完全移除，见到旧命令一律换 `filters.smrf` 管线写法；低版本可能没有 `filters.expression`，`filters.range` 虽在但自 2.5 起推荐 `filters.expression`、将在 3.0 弃用。Python 侧 `pip install PDAL` 依赖系统已装 PDAL 库（需 `pdal-config`），PyPI 的 `pdal` 3.5.5 与主库 2.10.2 是两套独立版本号，不要混为一谈。
- **验证产物**：点云用 `pdal info --summary out.laz` 核对 `num_points`、`bounds`、`srs`（转换前后的点数差异要能解释，比如裁剪后减少、去噪后仍保留全部点仅标 Class=7）；DEM 用 `gdalinfo -json dem.tif` 看波段数与范围，注意 `writers.gdal` 默认 `output_type: "all"` 会输出多波段，要单波段必须显式写 `idw`/`mean`。管线先 `pdal pipeline --validate` 再实跑，退出码 0 不能证明结果正确；DEM 或点云渲染图用 `read_image` 看一眼，成品用 `present` 交付。
- **风险与权限**：`pdal translate` 与各 writer 按 `filename` 覆盖同名输出，先确认目标文件名、换名或备份；`filters.outlier`、`filters.smrf` 需要全局统计、不能流式，大点云先按 tile 拆分，别一次把整片读进内存。拉取 Docker 镜像、下载大点云、安装 PDAL、写用户目录外的路径前用 `ask_user_question` 让用户选方案；SMRF 参数（`window`、`slope`、`threshold`）改动会影响地面分类结果，交付前说明用了哪组参数。
- **常见失败**：`Couldn't create <cls> stage of type '<type>'` 是 stage 名拼错或版本没有该 stage，先 `pdal --drivers` 确认；`pipeline` 解析失败用 `--validate` 定位 JSON 语法与顶层结构；`filters.reprojection` 报缺 SRS 补 `out_srs`（数据本身无坐标系时再给 `in_srs`）；重投影后精度变差在 writer 设 `scale_x/y/z` 与 `offset_x/y/z: "auto"`；Python 侧 `execute()` 返回点数不是数组，数据在 `pipeline.arrays`，失败看 `pipeline.log`。
