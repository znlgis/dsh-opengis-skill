## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference 目录；`projinfo` 的 WKT 输出动辄上百行，重定向到文件再分段 `read`/`grep`，或直接加 `-q`（只出字符串本体）、`-o PROJJSON -q`（结构化，可交给 `jq`），不要把整段 WKT 贴进上下文。工具清单与坑都在正文；重投影栅格/矢量文件改用 `skill` 加载 `gdal`，`ST_Transform` 侧加载 `postgis`。
- **执行环境**：`projinfo`、`cs2cs`、`proj`、`cct`、`projsync`、`geod` 都在 `ops_bash` 里跑。正文的 heredoc（`<<'EOF'`）在 bash 可用、在 `pwsh` 不可用，Windows 优先用管道 `echo 39.907 116.391 | cs2cs EPSG:4326 EPSG:32650`，或把坐标写成文件再重定向。设数据目录在 bash 是 `export PROJ_DATA=...`，在 `pwsh` 是 `$env:PROJ_DATA = "C:\OSGeo4W\share\proj"`。本机 PROJ 一般随 GDAL/QGIS 安装包（OSGeo4W）自带，`command -v projinfo` 找不到时先定位其 bin 目录。
- **先探测版本**：`projinfo --version` 会同时打印版本与 `proj.db` 路径，是最可靠的入口；`projinfo --searchpaths` 看搜索路径。`proj` 直接执行会进交互模式，不能当版本检查用。正文按 PROJ 9.9.0 编写：9.1 起变量是 `PROJ_DATA`（旧名 `PROJ_LIB` 仍兼容），9.3 起 `proj` 才能直接接受 `EPSG:xxxx`；低版本遇到 `PROJ_DATA` 不识别先查 `--version` 实际值。`projinfo --list-crs` 确认某个 EPSG 代码在本地库里是否存在。
- **验证产物**：用已知点对拍——`echo 39.907 116.391 | cs2cs EPSG:4326 EPSG:32650` 应得到东坐标约 44 万、北坐标约 442 万，量级明显不对通常是轴序或单位问题；`echo 30.5 114.0 | cs2cs EPSG:4326 EPSG:4547` 核对 CGCS2000 3 度带结果。转换路径用 `projinfo -s EPSG:4326 -t EPSG:4547 --summary` 看候选操作与精度，结构化核对用 `projinfo -o PROJJSON -q EPSG:4326`。批量转换后抽首尾各一行回算，逐行只打日志不算验证。
- **风险与权限**：`projsync --all` 会从 CDN 下载数 GB 网格、`PROJ_NETWORK=ON` 也会联网，先确认网络与磁盘，用 `projsync --bbox` 按区域只取需要的网格；`sqlite3 proj.db` 只做只读查询，不要写库。改 `PROJ_DATA` 会连带影响同机 GDAL/QGIS/PostGIS 的坐标运算，动手前用 `ask_user_question` 让用户确认；涉及基准面转换的成果，交付时要说明用了哪个转换、精度多少、是否需要 `--only-best`。
- **常见失败**：`Cannot find proj.db` 查 `PROJ_DATA` 与 `projinfo --searchpaths`；`DATABASE.LAYOUT.VERSION` 不匹配是多套 PROJ 副本混用；`The EPSG code is unknown` 是本地库没有该码，升级 PROJ 或改用等效 WKT/PROJJSON；`cs2cs` 输出轴序相反用 `-r` 反输入、`-s` 反输出；精度不足加 `projsync` 网格与 `--only-best`，否则会静默退回低精度操作。
