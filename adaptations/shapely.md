## DeepSeek Harness 使用建议

- **加载与引用**：正文主文件给类型、双 API、创建与常见问题，完整构造操作、谓词、集合运算、度量、STRtree、仿射与线性参考在 `reference/operations-reference.md`。先用 `read` 读该文件开头的小节目录定位，再 `offset`/`limit` 分段取用，或 `grep` 搜函数名（如 `coverage_clean`），不要整份读进上下文。矢量表读写用 `skill` 加载 `geopandas`，坐标投影按正文「坐标投影」一节用 pyproj，QGIS 内几何计算加载 `pyqgis`。
- **执行环境**：命令走 `ops_bash`（Windows 是 MSYS bash），Python 解释器要用装了 shapely 的那一个，先 `python -c "import sys; print(sys.executable, sys.version)"` 确认不是 QGIS/GDAL 自带环境，否则可能装到别的 site-packages。正文的 `pip install shapely` 在 Windows 上同样可用（wheel 自带 GEOS），但装包前需用户同意；纯命令行的 Windows 专有操作（`Get-ChildItem`、`$env:PATH`）走 `pwsh`。批量处理十万级几何用后台作业跑，`job_output` 收进度、`job_kill` 收尾。
- **先探测版本**：正文按 Shapely 2.2.0 编写（Python 3.11+、NumPy >= 1.26、GEOS >= 3.10，PyPI wheel 内嵌 GEOS 3.14）。先跑 `python -c "import shapely; print(shapely.__version__, shapely.geos_version)"` 拿到两个版本：GEOS 低于门槛的函数会直接报错或缺失——`concave_hull`/`remove_repeated_points` 要 3.11，`coverage_simplify`/`has_m`/`get_m` 要 3.12，`coverage_clean` 要 3.14，顶层 `shapely.split` 要 3.15（低版本回退 `shapely.ops.split`）；`multithreading_enabled` 与 `shapely.ops.transform` 在 2.2 已弃用，改 `shapely.transform`/`shapely.transform_coordseq`。
- **验证产物**：先用 `shapely.is_valid(g)` 与 `shapely.is_valid_reason(g)` 报出无效原因，再断言面积/长度量级；序列化回读 `shapely.from_wkt(shapely.to_wkt(g, rounding_precision=-1)).equals(g)`，改过几何后再核对 `geom_type` 与 `get_num_geometries()`。正文的端到端验收标准可直接照用：`clipped.geojson` 每个 Feature 能被 `shapely.from_geojson()` 读回、`is_valid()` 全为 True、面积与输入同阶。产出的图（`shapely.plotting` 或后续渲染）用 `read_image` 真看一眼，成品用 `present` 交付。
- **风险与权限**：`pip install shapely`、升级 GEOS 环境、改共享 conda 环境前用 `ask_user_question` 确认；`set_coordinates()`/`shapely.prepare()` 是原地修改，动手前先 `.copy()`，覆盖用户数据文件前先备份或换输出名。WKT/坐标导出前确认数据敏感度（精确坐标可反推位置），大几何别 dump 到终端刷屏，写到文件再 `read` 分段看。
- **常见失败**：`TopologyException: side location conflict` 基本是输入自相交，先 `make_valid()` 再算，不要用 `buffer(0)` 糊过去；面积/距离为 0 或极小是地理坐标系按度算，先投影到米制；`contains` 对边界点返回 False，改用 `covers()`；OOP 与函数式结果不同是 `buffer` 默认 `quad_segs` 不同（16 vs 8），比较前显式传参；`STRtree` 查空先排除 `None`/`Empty` 与 CRS 不一致。
