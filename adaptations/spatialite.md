## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference；加载方式见「环境准备」与「核心 API → 加载扩展」，DDL 与函数表见「核心 API」，端到端导入查询导出见「典型工作流」，报错对照见「常见问题」。GDAL 侧的导入导出用 `skill` 加载 `gdal`，Python 侧读写用 `skill` 加载 `geopandas`，坐标转换细节加载 `proj`。
- **执行环境**：命令走 `ops_bash`（Windows 是 MSYS bash）；Linux 的 `sudo apt install libsqlite3-mod-spatialite` 在 Windows 不可用，改用 conda-forge：`conda install -c conda-forge libspatialite`（会同时给出 `mod_spatialite.dll` 与 `sqlite3`），或解压官方 Windows 包后把 DLL 目录加进 PATH。`.load mod_spatialite` 是 sqlite shell 的内置命令而不是 SQL，Windows 下要写成 `.load mod_spatialite.dll` 并注意 shell 与 DLL 位数一致。一次性执行按正文写法把选项放库文件之前：`spatialite -cmd ".load mod_spatialite" mydb.sqlite "SELECT spatialite_version();"`；多条语句用 heredoc 从 stdin 送 `.load` + SQL，比转义引号稳。批量导入与大表建索引放后台作业，`job_output` 收进度、`job_kill` 收尾。
- **先探测版本**：正文按 libspatialite 5.1.0（2023-08-04）与 spatialite-tools 5.1.0a 编写，截至 2026-11 仍为最新。先按正文三条验证依次过：库文件是否存在（Windows 是 `mod_spatialite.dll`）、CLI 能否加载并报版本 `spatialite -cmd ".load mod_spatialite" :memory: "SELECT spatialite_version();"`（Windows 上把库名写成 `mod_spatialite.dll`）、Python 侧 `python -c "import sqlite3; c=sqlite3.connect(':memory:'); c.enable_load_extension(True); c.load_extension('mod_spatialite'); print(c.execute('SELECT spatialite_version()').fetchone())"`；三条任一失败先解决加载问题，再动 SQL。发行版包常落后（如 bookworm 是 5.0.1），4.x 与 5.x 函数集不同（`GeosMakeValid`、`InitSpatialMetaData` 重载 5.x 才齐全），拿到版本号再决定用哪个函数名。
- **验证产物**：导入或建索引后回读 `geometry_columns`：`SELECT f_table_name, f_geometry_column, geometry_type, srid, spatial_index_enabled FROM geometry_columns;` 确认几何列、SRID 与索引开关；再跑 `SELECT CheckSpatialIndex('表','geom');` 确认 RTree 与主表同步，返回 -1 就是没建好。导出的 GPKG 用 `ogrinfo -so out.gpkg 图层名` 核对要素数与 CRS。查询结果先 `SELECT count(*)` 再抽样几行，确认单位没有混用（4326 下 `ST_Distance` 返回度，米制要 `ST_Transform` 到 3857）。成品库文件用 `present` 交付。
- **风险与权限**：`DROP TABLE`、`DisableSpatialIndex`、批量 `DELETE`/`UPDATE` 都改不回旧状态（事务只保护单次会话），执行前先备份 `.sqlite` 文件或复制成新路径，并用 `ask_user_question` 给「先备份 / 换新库 / 直接改」三个选项。GDAL 的 `-dsco SPATIALITE=YES` 会重建库结构，覆盖已有输出前先确认；`InitSpatialMetaData` 对已初始化库重复调用返回 0、不破坏数据，但仍应只跑一次。
- **常见失败**：`no such function: InitSpatialMetaData` 是扩展没加载或加载的是空壳库，先 `.load` 再用 `spatialite_version()` 验证；`no such module: mod_spatialite` 给绝对路径加载；CLI 里 `.load` 报失败先查 shell 与库位数/构建是否匹配，再改用 Python 或 `ogrinfo` 路径；`CreateSpatialIndex` 返回 -1 是表里有名为 `rowid` 的物理列遮蔽了真 ROWID，重命名后再建；`geometry has invalid SRID` 是混入 SRID -1/0 的几何，用 `GeomFromText(wkt, 4326)` 赋回；查询慢是只用 `ST_Distance` 没加 `MbrWithin` 粗筛。
