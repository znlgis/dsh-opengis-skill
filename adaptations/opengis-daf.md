## DeepSeek Harness 使用建议

- **加载与引用**：单文件技能，无 reference 目录；正文的「方案配置」「内置算子」「CLI 命令」「常见问题」是查表区，按小节定位即可。正文提到的 `docs/plan-config-guide.md`、`docs/operator-reference.md` 在上游仓库里，clone 后才有、不在技能目录内，别用 `read` 硬找。需要几何语义用 `skill` 加载 `nettopologysuite`，GDAL 绑定细节加载 `opengis-utils-for-net`。
- **执行环境**：`git clone --recurse-submodules` 走 `ops_bash`（漏 `--recurse-submodules` 会缺 `opengis-utils-for-net` 子模块，编译期报 GDAL 绑定类型缺失）；`dotnet` 系列与 `.\build.ps1`、`demo/run-demo.ps1` 走 `pwsh`。要求 .NET SDK 10.0（`global.json` 锁 10.0.301），没有就如实报告，不要拿 .NET 8/9 硬编。克隆目录与 `plans/` 放会话工作区；长构建用后台作业加 `job_output` 收日志。
- **先探测版本**：正文按 .NET SDK 10.0.301（C# 14）编写；`dotnet --version` 与 `dotnet --list-sdks` 确认 10.0.301 在列；`dotnet build OpenGisDAF.slnx --configuration Release` 成功后 `dotnet run --project src/OpenGisDAF.Cli -- help` 确认 CLI 可用。本项目无 Release tag、无 NuGet 包，别写 `dotnet add package OpenGisDAF`；SDK 低于 `global.json` 要求时会直接拒绝构建。
- **验证产物**：先 `daf validate --plan plans/my.json`（只校验 21 条规则）再 `daf run --plan plans/my.json`，退出码 `0` 才算成功（失败或跳过都返回 1）。QC 方案额外生成 `{plan}.qc-report.json`，看 `totalChecked`/`failed`/`passRate` 与 issue 清单；非 QC 方案不生成该文件。输出 GeoJSON 用 `ogrinfo -so` 或 `read` 回读核对 `crs`、要素数、字段。测试必须两步：先 `dotnet build OpenGisDAF.slnx -c Release` 再 `dotnet test OpenGisDAF.slnx -c Release --no-build`，同一条命令会报「运行了零个测试」并退出码 5。
- **风险与权限**：`daf plan` 写 `%APPDATA%\opengis-daf\plans`，`copy`/`export` 会覆盖同名方案；PostGIS 输出的 `encryptedPassword` 只接受当前用户生成的 DPAPI/AES-256-GCM 密文，明文直接失败且不回显密文。目标表已存在报 `Layer already exists` 是有意防误覆盖，删表或换表名都要先问用户；`buffer` 的 `distance` 单位随数据坐标系，EPSG:4326 下 800 就是 800 度。删表、覆盖方案、连生产库前用 `ask_user_question` 给选项。
- **常见失败**：`dotnet test` 报「运行了零个测试」+退出码 5 是 xunit.v3 工具链的固有行为，按上面两步走；缺子模块时编译报 GDAL 类型缺失，重新 clone 带 `--recurse-submodules`；插件算子不出现，先查是否把 `OpenGisDAF.Core.dll` 复制进插件目录（类型不同源会被静默跳过），且 `daf operator import` 只对当前进程有效，要让插件参与 `daf run` 必须用同进程宿主。
- **交付**：方案 JSON、QC 报告、输出 GeoJSON/Shapefile 都以工作区相对路径写回复，成品用 `present` 列出；qc-report 里的 WKT 违规几何可单独抽成文件再给用户。
